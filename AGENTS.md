# OtakuHaven

> A home for otaku — browse all anime, enter any anime, meet its characters. Every character gets a fun description.

## Project Facts

- **Stack**: Next.js 16 (App Router) + TypeScript + Tailwind CSS 4 + ESLint. Node 20.9+ (project runs Node 24).
- **Data**: AniList GraphQL API (`https://graphql.anilist.co`), no API key. ~90 req/min public limit.
- **Deploy**: Vercel. Name: OtakuHaven.
- **Repo**: own repository at `D:\Zero\Anime` (origin: `anishinsei-343030/otaku-haven`). HQ repo never tracks this folder (gitignored).

## Commands

- `npm run dev` — dev server
- `npm run lint` — ESLint (no warnings allowed)
- `npm run build` — production build (must pass before deploy)
- `npm run start` — serve built app

## Rules

- **Never hardcode AniList responses** — always use `src/lib/anilist.ts` and its typed helpers.
- **Server components fetch**; client components only for interactivity (favorites, Fun Mode toggle, random button, search-as-you-type). Pass serializable props, never fetch in client unless unavoidable.
- **Cache discipline**: server fetches use `revalidate`; never disable caching globally. Add `Cache-Control: public, max-age` headers only via the lib.
- **HTML stripping**: all descriptions from AniList contain HTML — strip server-side in `lib/anilist.ts`.
- **Banner fallback**: `bannerImage` is often null — UI must always have a gradient fallback.
- **Fun Mode**: every character gets a fun blurb — curated in `data/fun-blurbs.json` (keyed by AniList character id), generated by the fallback in `lib/fun.ts` otherwise. The Fun/Real toggle is a client preference persisted in localStorage.
- **Never commit secrets**. There are none in this project.
- Verify before claiming: build + lint must pass, then a dev-server click-through of the core flow (anime → characters → character page).
